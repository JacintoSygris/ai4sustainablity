# Runtime XBRL concept identification v1

Ranked concepts support human identification review. Acceptance does not change
tagging, factual approval or materiality, and reviews do not train the model.
The feature uses no external API and makes no filing or conformance claim.

## Private inference

`POST /xbrl/concept-candidates` on the private loopback Python service.
`Authorization: Bearer <I4S_AI_API_TOKEN>`. Missing token/model configuration: 503;
wrong/missing credentials: 401; flag off: 404 without loading artifacts.
One nonblocking worker slot, separate from predictions; busy: 503, `Retry-After: 10`.
Raw body max 32 KiB, streamed before parsing; body deadline five seconds.
Unknown fields are rejected (422). No text, tokens, file paths or response bodies
are logged by this endpoint. No account identity, values or documents are sent.

Request (all object schemas closed):

| Field | Type / constraint |
|---|---|
| schema_version | literal `xbrl-runtime-identification-v1` |
| request_id | UUID generated by Laravel |
| taxonomy_profile | server-selected profile ID, ≤100 characters |
| catalog_sha256 | lowercase SHA-256 of exact catalog bytes, or exact concept-map bytes in map-only training |
| indicator | object below |
| indicator.label | string ≤300 characters, required, may be empty |
| indicator.description | string ≤4,000 characters, required, may be empty |
| indicator.language | language tag ≤16 characters; unsupported languages abstain |
| indicator.standard | optional/null canonical `ESRS 2`, E1–E5, S1–S4, G1 |
| indicator.dr | optional/null canonical BP/GOV/SBM/IRO/MDR or topical DR code, ≤40 characters |
| indicator.value_type | optional/null text, number, monetary, integer, boolean, enumeration, date, nil |
| indicator.unit | optional/null string ≤64 characters; currency uses ISO 4217 code; dimensionless numeric uses `pure` |
| indicator.period_type | optional/null `instant` or `duration` |

At least label or description must contain non-whitespace text. Wording is
preserved verbatim. There is **no datapoint prerequisite**. Missing DR/standard
contributes zero prior. Textual overlap is checked independently of DR tokens.
Both request validators reject unknown DRs and contradictory standard/DR pairs
(422). Supported Set 1 topical DR ranges are E1: 1–9, E2: 1–6, E3: 1–5,
E4/E5: 1–6, S1: 1–17, S2/S3/S4: 1–5, G1: 1–6. BP/GOV/SBM/IRO/MDR
codes belong to ESRS 2. Dotted topical references are not supported. The direct
runtime matcher also abstains with `unsupported_context` before ranking invalid
contexts, independently of the fitted model's DR priors.

Response: same schema_version/request_id; model_version, artifact_sha256 (exact
manifest bytes), catalog_sha256, concept_map_sha256, taxonomy_profile and nullable
package_sha256; candidates (0–5); abstained (boolean); reason_codes (0–1).
Each candidate: QName, rank (contiguous 1-based), score (finite, [0,1]),
validation_status (`map_only`, `unverified`, `verified_taxonomy`) and bounded
validation_reasons. QNames are unique; scores descend, ties use QName order.
Scores are **uncalibrated ranking scores**, not probabilities of correctness.

Abstention reasons: `unsupported_context`, `unsupported_language`,
`zero_textual_overlap`, `no_compatible_candidates`, `below_threshold`,
`insufficient_margin`. The immutable artifact owns score/margin thresholds.
Incompatible candidates are filtered. The conservative resolved-type allowlist
never treats an unknown custom type as verified. Composite/dimensional semantics
and general unit compatibility are not implemented.

## Laravel authority

All routes use existing web/session, private-dev-user, auth, verified.required
and CSRF middleware. Separate per-user throttle keys:

- GET `/api/report/xbrl-identifications`: 30/min; `page`, `per_page` ≤50;
  envelope `data: {runs, page, last_page}`.
- POST `/api/report/xbrl-identifications`: 5/min; closed JSON
  `{indicator, reporting_fact_id?, datapoint_id?}`; 201 `data: run`.
- POST `/api/report/xbrl-identifications/{run}/reviews`: 20/min; closed JSON
  `{candidate_qname, decision: accepted|rejected, reason, expected_sequence}`;
  reason nonblank ≤1,000 characters; 200 `data: run`.

`run` contains immutable input_json, input_sha256, context_sha256, response_json,
identities, creation time, owner-scoped subject and append-only reviews. The
response_json also retains the exact Python `service_response`; outer candidate
validation is Laravel's independent assessment and may be `incompatible`.
If all returned candidates are locally incompatible, the authoritative result
abstains with `no_compatible_candidates`; the original `service_response` stays
verbatim. Existing service abstentions remain intact.
`validation_context` freezes the local validation mode, taxonomy profile and
verified package SHA-256 (null only when no package is configured).
Review sequence starts at 1; expected_sequence is 0 before the first review.
Reviewer ID and UTC time are supplied by the session/server, never the browser.

Ownership comes only from `Characterization::forUser()`. Foreign run/fact IDs:
404. Unknown/out-of-scope datapoints: 422. Subjects are server-derived `fact:id`,
`datapoint:id`, or newly generated `custom:uuid`. Each new free-description run
has a new custom subject; history review retains its original subject. No
free-description binding to a datapoint is inferred.
For linked facts Laravel derives value_type and unit from the owned stored fact,
rejects contradictory non-null browser overrides (422), and sends/persists the
derived metadata. Acceptance rechecks it, including for previously persisted
runs. Factual values never go to Python.

Inference runs outside transactions. Characterization is locked before linked
fact/run; context hashes capture characterization, facts, reporting profile,
current corpus, model/catalog and validation package identity. Changes during
inference or before acceptance: 409. expected_sequence guards racing reviews.
One active acceptance per subject across runs; reject it first. Rejection is
always available for a persisted candidate, including obsolete artifacts, so
operators can revoke stale acceptances without reprovisioning old models.
Acceptance requires a non-abstained `map_only` or `verified_taxonomy` candidate;
`unverified`/`incompatible` cannot be accepted. Map-only acceptance is explicitly
limited to reviewed identification and never changes renderer mappings.

The client allows numeric loopback HTTP only; no redirects, proxies or retries;
connect timeout 2 s, total 10 s; response sink ≤32 KiB. Identities, exact map and
IG-3 input hashes, ordered unique ranks, scores and QName membership are checked
independently. An unconfigured external package yields map_only; any configured
invalid package/catalog fails closed. Catalog-only concepts require verified
package metadata. Decisions are audited without copying indicator text into the
audit event.

Private rows cascade through account/characterization deletion. Deleting a fact
nulls its FK and retains the original subject and review history while the
account exists. All mutations use the services; ordinary model updates of runs
or reviews throw. There is no edit/delete API or CSV export.

## Frozen evidence

With the flag enabled, new snapshots capture optional
`source_manifest.xbrl_identifications`:
`{schema_version: xbrl-identifications-evidence-v1, records: [...], sha256}`.
Only reviewed runs are included, with exact inputs/results and the entire
review history. The records digest and snapshot digest cover this evidence.
Maximum 1,000 reviewed runs per snapshot; exceeding it fails explicitly.

Snapshot schema validation, IR and evidence-bundle export use frozen bytes,
without model/catalog reads. Later decisions require a new snapshot and approval.
Disabled flags do not rewrite historical evidence. Legacy snapshots with no
identification section remain valid. The identification section is never read
by the renderer to select tagging concepts.
